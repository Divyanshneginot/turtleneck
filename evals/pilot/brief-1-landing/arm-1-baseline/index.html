System Philosophy

The Three Pillars of Turtleneck Intelligence

How Turtleneck rewires the cognitive reasoning of LLMs before they write a single line of HTML or CSS.

01 / CONCEPTUAL FOUNDATION

Concept Over Template

Stops agents from defaulting to lazy SaaS boilerplate. Turtleneck forces the model to deliberate on the emotional tone, user ergonomics, and conceptual metaphor of the tool before choosing layout structures.

RULE: Ban generic cards & purple gradients. Derive unique component geography from domain mechanics.
02 / INSPIRATION TRANSLATION

Translate, Never Plagiarize

When shown reference websites, naive models copy HTML tags and hex colors verbatim. Turtleneck deconstructs references into fundamental visual vectors—tension, density, contrast, and rhythm—then re-synthesizes them anew.

RULE: Extract structural essence and emotional cadence; never duplicate literal DOM structures.
03 / SYSTEMIC RIGOR

Systemic Coherence

Prevents multi-turn design drift. Turtleneck maintains strict token invariants across typography, elevation planes, micro-states, and optical margins so complex generated web applications feel unified.

RULE: Every state (hover, active, disabled, empty) inherits harmonic mathematical scaling.

Add directly to your repository's .cursorrules or global rules
.cursorrules MARKDOWN 
# Turtleneck UI/UX Design Intelligence Protocol
- Never build standard generic purple-gradient SaaS cards unless explicitly asked.
- Before generating frontend code, synthesize a specific Aesthetic Archetype:
  1. Determine domain metaphors (e.g. tactile audio deck, brutalist archive, quant desk).
  2. Define a strict harmonic token palette (max 3 accents, intentional background depth).
  3. Ensure tactile micro-interactions on all interactive surfaces.
- Strictly adhere to typographic hierarchy: Display headers, crisp mono data tags, sans body.
Save to .cursorrules at project root to steer all Cursor Composer and Chat generations.
