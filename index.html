02 // The Manifesto

Ten principles of product-design intelligence.

01

Decide, then make.

Do not decorate an undefined product. Determine what the user must understand, what they must decide, and what feedback makes the next action obvious.

02

Archetype belongs to the job, not fashion.

Dark mode is not a default. Monitoring requires dense data grids; consequential choices require guided recommenders; starting points require template builders.

03

Scale tension over cosmetic clutter.

Establish dramatic contrast between large display type and minute metadata before adding arbitrary borders, shadows, pills, or gradients.

04

Contrast is a mathematical contract.

Normal text clears 4.5:1 against canvas. Graphical controls clear 3.0:1. "Accessible" is not a vibe; it is an asserted calculation.

05

Motion communicates causality.

Micro-feedback is 80–140ms. Animate transform and opacity; never transition: all. Never introduce motion that blocks the user's next action.

06

The happy path is not the product.

A UI is incomplete if only its default state is designed. Specify hover, active, focus-visible, disabled, loading, empty, and error retry states.

07

Guided choice beats the blank canvas.

When users are uncertain, guide them through a 3–7 question recommender with deterministic scoring and explainable rationale.

08

Adaptive tempo prevents ceremony.

Direct mode ships tiny fixes instantly without an interview. Fast path builds when scope is known. Discovery pitches 2–3 options on greenfield briefs.

09

Respect the local vernacular.

Inspect existing tokens, typography, and component conventions first. Repair inconsistencies rather than layering a second design system over them.

10

Prove, don't promise.

Every rule must be backed by an automated check. 86 test gates verify contrast, focus rings, reduced-motion, and reference consistency on every build.
